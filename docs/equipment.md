# 장비 신청
노트북 교체는 지급 후 4년이 지나면 신청할 수 있다.
모니터 추가 신청은 팀장 승인 후 총무팀에 요청한다.


## v0 — 베이스라인 (2026-11-16)

**목표**
로컬 7B 모델이 스키마만 보고 얼마나 SQL을 맞히는지 기준점 측정.

**설정**
- 모델: qwen2.5-coder:7b (Ollama, CPU, temperature 0)
- 프롬프트: 스키마(CREATE 문) + 질문
- 평가: 실행 정확도 (정답 SQL과 결과 행 비교)

**결과: 10/15 (66.7%)**
| 난이도 | 정답 |
|---|---|
| easy | 5/5 |
| medium | 4/5 |
| hard | 1/5 |

**오류 분석**
| 유형 | 문항 | 내용 |
|---|---|---|
| 데이터 값 모름 | q10 | '공식몰'을 channel 값으로 착각 (실제로는 매장명) |
| 컬럼 위치 착각 | q11 | quantity를 products에서 조회 → SQL 에러 |
| 집계 단위 오해 | q14, q15 | 월 대신 일 단위, 상품별 합계 대신 단건 최댓값 |
| 출력 형식 | q09 | 반올림 지시 무시 |

**발견**
- q13은 틀린 로직(단일 상품 기준)이 우연히 정답과 같은 결과를 냈음.
  → 실행 결과 비교 방식은 "우연한 정답"을 걸러내지 못함. 채점 방식의 한계로 기록.

**다음 가설**
- 범주형 컬럼의 실제 값 목록을 주면 값 매핑 오류(q10)가 줄 것이다. → v1
- SQL 에러를 모델에게 돌려주고 재시도시키면 q11 유형이 해결될 것이다. → v2

## v1 — 컬럼 값 힌트 추가 (2026-11-18)

**가설**
범주형 컬럼의 실제 값 목록을 주면 값 매핑 오류(q10)가 줄 것이다.

**변경**
프롬프트에 `[컬럼 값 참고]` 추가: stores.name/region/channel, products.name/category의
실제 값 목록과 sales.sale_date 범위 (DB에서 자동 추출).

**결과: 10/15 (66.7%) — 총점 동일, 내용 변화**
| 난이도 | v0 | v1 |
|---|---|---|
| easy | 5/5 | 5/5 |
| medium | 3/5 | 4/5 |
| hard | 2/5 | 1/5 |

| 문항 | v0 → v1 | 원인 |
|---|---|---|
| q10 | X → O | 값 힌트로 '공식몰'이 매장명(stores.name)임을 인식 ✅ 가설 확인 |
| q12 | O → X | **회귀.** 별칭 혼동(sales를 s로 두고 매장명을 s.name으로 조회 → SQL 에러) |

**배운 점**
- 총점만 보면 "효과 없음"이지만, 문항별로 보면 의도한 개선 1건 + 회귀 1건.
  → 문항 단위 추적이 필요한 이유.
- 프롬프트가 바뀌면 temperature 0이어도 SQL 작성 스타일(별칭 등)이 바뀌고, 새 실수가 생길 수 있음.

**다음 가설 (v2)**
현재 오답 중 q11, q12는 SQL 실행 에러로 실패했고, 에러 메시지가 원인을 정확히 알려준다.
→ 에러 메시지를 모델에게 돌려주고 재시도하게 하면(최대 2회) 두 문항이 해결될 것이다.
